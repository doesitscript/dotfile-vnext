How to Fix the 0x800705AA Error1. Check Group Policy RestrictionsHyper-V may be blocking the GPU partition due to group policy requirements.Open the Registry Editor (regedit) on the host.Navigate to HKEY_LOCAL_MACHINE\SOFTWARE\Policies\Microsoft\Windows\HyperV (if the keys don't exist, create them).Create (or set) the following DWORD (32-bit) values to 0:RequireSecureDeviceAssignment = 0 RequireSupportedDeviceAssignment = 0

. Ensure Enough Physical VRAMThe 0x800705AA error occurs if the VM asks to partition more VRAM than your host GPU has available, or if the host is running low on system RAM.Ensure the VM is not set to use Dynamic Memory, which conflicts with GPU partitioning. Disable this in the VM's Hyper-V memory settings.If you are assigning 100% of the GPU's memory to a single VM partition, it can cause the VM to fail to start. Try reducing the PartitionVram value in your Easy-GPU-PV or PowerShell script to assign 50% to 90% of your GPU's total VRAM.3. Restart the Hyper-V ServiceA stalled service on the host may hold onto GPU resources.Open Services on the host machine (services.msc).Find Hyper-V Virtual Machine Management Service.Right-click and select Restart.4. Disable Checkpoints and Enhanced SessionsKnown community issues suggest that Checkpoints and Enhanced Session Modes can interfere with GPU-P initialization.Open Hyper-V Manager, right-click your VM, and go to Settings.Under Management, select Integration Services and ensure Enhanced Session Mode is unchecked.Ensure VM Checkpoints are disabled in the VM properties while troubleshooting.If the above steps don't resolve the error, please let me know:How much total physical RAM/VRAM your host system has.Which script or method (e.g., Easy-GPU-PV) you are using to map the GPU.If the GPU is being assigned at 100% or a lower fractional percentage.
