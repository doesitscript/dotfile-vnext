# Post-infrastructure storage follow-up

**Date:** 2026-09-11
**Status:** applied, re-verified, and idempotence-accepted

## What changed

- Reapplied the repository-owned data-disk path. The existing 300 GiB cache
  VHDX and 32 GiB logs VHDX remained attached; guest labels and mounts were
  reconciled.
- Reapplied native kubelet pod logs at `/mnt/k3s-logs/pods`.
- Re-ran vLLM stale-ReplicaSet cleanup; no stale zero-replica ReplicaSets
  remained.
- Re-verified all three host SSDs by exact serial and label. No second wipe was
  needed: `K3S-LOGS-HOST`, `K3S-CACHE-HOST`, and `K3S-COLD-HOST` were already
  correct.
- Corrected the SSD role and Linux filesystem-label task so matching state is
  verified without mutation. Both SSD `apply=true` and the full guest storage
  reapply completed with `changed=0` after convergence.
- Refreshed the storage report. Root is 21% used, cache is 29% used, logs are
  1% used, and both VHDXs remain separate non-RAID dynamic disks.

## What is different from the original plan

- Do not create RAID0, combine SSDs, or move pagefile/hibernation/Prometheus
  data onto the cache disk.
- Treat the three physical SSDs as separate host NTFS volumes. Use the
  serial-bound repurpose playbook only when a label or partition must actually
  change; its apply path is destructive.
- Treat the guest VHDXs as the active K3s storage contract: cache/containerd/
  local-path on `k3s-cache`, native pod logs on `k3s-logs`.
- Reapply in this order: `deploy_k3s_data_disk.yaml`,
  `configure_k3s_pod_logs_dir.yaml`, `cleanup_vllm_stale_replicasets.yaml`,
  then `report_storage.yaml`, always with explicit limits.

## Remaining work

- No storage implementation work remains for this plan.
- The idempotent current-state contract is now the acceptance standard for
  future storage changes: rerunning the authoritative playbooks must produce
  `changed=0` when state already matches.
- Remaining model deployments are workload validation, not storage migration.
- Future use of `K3S-COLD-HOST` needs a separate approved workload contract;
  it is not wired into K3s by this plan.
