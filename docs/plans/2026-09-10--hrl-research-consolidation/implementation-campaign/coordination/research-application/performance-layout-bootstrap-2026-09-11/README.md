# Bootstrap research-application receipt — performance layout

## Purpose and provenance

This folder records the first bootstrap use of the guided research-application
loop. Its source is the user-and-On-site-Expert collaborative evaluation:
[storage-performance-research-application.md](../../../../multi-agent-design/multi-agent-onsite-expert/examples/storage-performance-research-application.md).

The source was produced through repeated focused research, cross-technology
comparison, verified current-state evidence, and user direction about using all
appropriate storage tiers. It is retained unchanged as a high-detail source;
this folder makes it consumable by Planner, Implementer, and Evaluator without
requiring them to rediscover or treat every example command as a mandatory plan.

## Pipeline interpretation

| Role | Bootstrap action represented here | Durable output |
| --- | --- | --- |
| User + On-site Expert | Framed capacity/performance outcome, corrected assumptions, focused research, challenged options, and selected a direction. | The source evaluation and constraints captured in its narrative. |
| Research Synthesizer | Classified evidence into hard corrections, placement principles, conditional options, prohibitions, and discovery requirements. | [Research-to-decision packet](research-to-decision-packet.md) |
| Planner / Coordinator | Mapped accepted guidance to campaign slices and repository ownership without creating a rigid implementation script. | [Plan-materialization brief](plan-materialization-brief.md) and the campaign decision ledger |
| Implementer / Evaluator | Future consumers: interpret approved principles through current live evidence and existing Ansible owners; independently prove the result. | Future implementation receipts and Evaluator verdict |

## Bootstrap limitation and future role behavior

This is a temporary bootstrap packet because the full multi-pass
Research-Synthesizer ↔ Expert → Planner orchestration is not yet runtime
scheduled. The governing future contract is
[guided research application](../../../../multi-agent-design/research-application-loop.md).
Future processing must begin with this packet and the canonical campaign
decision ledger, then make only targeted updates from fresh evidence. It must
not start a broad repeat of the original research or assume the source itself
grants Apply authority.
