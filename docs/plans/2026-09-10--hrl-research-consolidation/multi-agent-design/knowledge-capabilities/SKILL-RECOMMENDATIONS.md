# Skill recommendations

These are concise implementation recommendations, not newly activated skills.

| Role/capability | Recommendation | Production home | Decision |
| --- | --- | --- | --- |
| Ansible implementation knowledge capability | Promote the existing design draft only after the storage effort plus two independent Ansible efforts prove a stable contract. It composes, rather than replaces, `ansible-knowledge-gate`. | `.cursor/skills/ansible-implementation-knowledge-capability/` | **One proposed new project skill; not yet.** |
| Researcher | Extend the existing researcher skill path to emit the bounded implementation-readiness brief when Ansible choices must be made. | Existing researcher skill/workflow integration | **Enhance; no new skill.** |
| Implementer | Extend the mature Implementer workflow to consume the readiness brief and record evidence-backed deviations in its normal receipt. | Existing Implementer skill/workflow | **Enhance; no new skill.** |
| Evaluator | Extend the mature Evaluator workflow with the capability-use review rubric and normal feedback/waiting/ready artifacts. | Existing Evaluator skill/workflow | **Enhance; no new skill.** |
| Onsite Expert/coordinator | Add capability selection and routing to its existing intake/routing path. | Existing Onsite Expert skill drafts/workflow | **Enhance; no new skill.** |
| HRL Librarian-as-Expert | Keep it an opt-in, broad research resource for durable knowledge gaps; do not turn it into an execution gate or a project-wide veto role. | Existing HRL `library-domain-expert` agent definition | **No new skill.** |

## New-role conclusion

No additional permanent role is recommended. The only potential new skill is
the narrow Ansible capability draft already located at
[`skill-drafts/ansible-implementation-knowledge-capability/SKILL.md`](skill-drafts/ansible-implementation-knowledge-capability/SKILL.md).
All other work should enhance the established roles by reference, preserving
their artifact ownership and avoiding duplicate authorities.
