# Beta iteration priorities

This iteration gives equal priority to making the original storage/cache work
executable and extending the multi-agent workflow. Avoid spending the iteration
only on orchestration experiments or unrelated project cleanup.

Requested outcomes:

- Verify whether the Coordinator/Researcher handoff can drive the original
  changes; state any remaining discovery, decisions, and implementation gaps.
- Extend or compose with the established Implementer and Evaluator skill packs,
  preserving their mature responsibilities and feedback contract.
- Connect preparation artifacts to an implementation campaign: discover current
  targets, turn the plan into owning Ansible roles/playbooks, validate, apply
  authorized changes, and independently evaluate the evidence.
- Keep the artifact identities and handoffs usable by a future larger
  orchestrator; this iteration need not build that entire orchestrator.
- Deliver two copy/paste launch prompts with the exact skills and plan paths.
- Add a lightweight, read-only observer skill and third prompt for this chat.
  Observe orchestration state and report brief useful changes; no new approval
  authority, extensive notes, or another controlling agent.

This iteration ends when those entrypoints and their handoff checks are ready
to use. Launching the agents and applying infrastructure changes is the next
campaign, not a prerequisite to delivering these three prompts. Preserve
existing authorization, while never guessing destructive storage targets or
treating preparation review as implementation approval.

Later iterations can expand automation and coordination after this usable
implementation/evaluation path has been exercised. The user's operating
principle remains: improve the work in scope, do not degrade the project, and
leave the work area slightly better—not demand a whole-project cleanup first.
